### Bugs found
- **BUG-64** (`POST /api/exercises`, Suite C): a non-array/non-string `tags` value (e.g. `tags:12345`, `tags:true`, `tags:{}`) throws an unhandled `TypeError` → bare 500 instead of a 400. Root cause: `app/api/exercises/route.ts` lines 54-58, the `typeof tags === 'string' ? ... : (tags ?? [])` fallback doesn't guard against non-array truthy values before calling `.length`/`.some()` on them.
- **BUG-65** (direct Supabase insert to `sessions`, Suite C): `title`/`notes` sanitization (`stripHtmlTags`) only happens client-side in `SessionBuilder.tsx`; a direct PostgREST insert with `<script>alert(1)</script>` persisted unsanitized. Evidence kept: session `2110823c-d109-48c3-b624-1dd0ed73818e`. RLS/enum protections are solid (verified no auth/injection bypass); no active XSS render path was found (JSX escapes it everywhere content is displayed today), but it's a latent stored-content risk. Recommend a DB-level sanitization trigger/CHECK.
- **BUG-66** (`POST /api/programmes/[id]/save-tree`, Suite C, **data loss**): the route deletes all of a week's existing `programme_sessions` *before* filtering out invalid entries in the new payload. A request containing even one session with an out-of-range `day_of_week` (e.g. 0) returns `{"ok":true}` while silently wiping every previously-saved session for that week and inserting nothing. Reproduced live (valid session → wiped by a single invalid-payload follow-up call, confirmed via direct DB query).
- **BUG-67** (`POST /api/portal/photos`, Suite C): file-type validation trusts the client-declared multipart `Content-Type` with no magic-byte check. A plain-text file declared as `image/png` was accepted, stored in the public bucket, and is served back with a forged `Content-Type: image/png` header (confirmed via `curl -I` on the public URL). Evidence kept: `progress_photos` row `5086483b-b06d-41f5-a4c1-ef39096ff574`.
- **BUG-68** (`PATCH /api/agreements/[id]`, Suite C): `parq_signed`/`waiver_signed`/`consent_signed` aren't type-checked before the DB write (unlike every other typed field on the same endpoint). A non-boolean value causes a raw Postgres error message to leak through as an unhandled 500 instead of a clean 400. Not exploitable (Postgres rejects the bad value, no corruption), but inconsistent and leaks internal error text.

### Bugs fixed
- **BUG-66 (HIGH)** — `POST /api/programmes/[id]/save-tree` deleted a week's existing `programme_sessions` *before* filtering invalid entries out of the incoming payload, so one out-of-range `day_of_week` silently wiped the week with `{"ok":true}` and no replacement (real data loss). Fix: validate every session in every targeted week up front; reject the whole request with 400 (no deletes) if anything fails validation. `app/api/programmes/[id]/save-tree/route.ts`. Verified live: valid session saved → replayed with one invalid session in the same week → 400, original session confirmed still present via re-fetch.
- **BUG-64 (MEDIUM)** — `POST /api/exercises` crashed with an unhandled 500 on `tags: 12345`/`tags: {}` (non-array/non-string) because `.length`/`.some()` don't exist on non-arrays. Fix: explicit `typeof`/`Array.isArray` guard → 400, matching the existing PATCH handler pattern. `app/api/exercises/route.ts`. Verified live: both bad-type cases now 400; valid string/array tags still 201.
- **BUG-68 (LOW-MEDIUM)** — `PATCH /api/agreements/[id]` didn't type-check `parq_signed`/`waiver_signed`/`consent_signed`, so a non-boolean value hit Postgres directly and leaked its raw error as a 500. Fix: boolean check added for the three fields, mirroring the `is_shared` check on `PATCH /api/exercises/[id]`. `app/api/agreements/[id]/route.ts`. Verified live: non-boolean `parq_signed` now 400.

**Not fixed — BUG-65 (MEDIUM, deferred).** Same root cause as the already-open Notion BUG-67/bug_reports ref 61 (SessionBuilder writes sessions/session_items directly to Supabase from the browser with only client-side sanitization) — re-confirmed still open, not a new issue. Properly fixing it needs a new `POST/PATCH /api/sessions` route plus switching `SessionBuilder.tsx` over to it, which is bigger than tonight's remaining budget justified. Notion updated with a re-confirmation note rather than a duplicate entry.

**Not fixed — BUG-67 (MEDIUM, deferred).** `POST /api/portal/photos` trusts the client-declared multipart `Content-Type` with no magic-byte check; a text file declared `image/png` was accepted and served back with a forged content-type header. Needs a signature-check or image-decode library — likely a new dependency, so deferred. Logged as new Notion BUG-71 (open).
