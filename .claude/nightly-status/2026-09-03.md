The most likely cause: the Vercel project's **Production Branch** setting is still `main` while every real commit lands on `master`, so Vercel correctly treats every push as a non-production branch and only builds a Preview.
- This is functionally the same class of failure the weekly-audit task's step 7 was written to catch (Vercel silently disconnected, 2026-07-13 → 2026-08-10) — just a different failure mode: the integration *is* connected and *is* building, it's just never promoting to Production automatically.

If it says `main`, change it to `master` (matching what's actually pushed) — or alternatively change the GitHub repo's default branch to `master`. Either fixes automatic Production deploys going forward. After the setting is corrected, this commit (`02de9ca`) or a fresh empty commit should be manually promoted/re-deployed to Production once to get the 3+ weeks of accumulated fixes live immediately.

**Impact:** every fix and feature shipped by the daily/weekly automated tasks since 2026-08-11 (at least 4 commits: `8acc86f`, and now `e34b536`/`02de9ca`) has not reached real users.
