### Bugs found
1. **`PATCH /api/client/docs` — empty string on a doc URL field 500s with a leaked Postgres error.** The account page's "Save document links" button always submits all three URL fields together; leaving any of them blank sends `""`, and the route only null-checks (not falsy-checks) before the DB write, so `""` hits `chk_{field}_url_protocol` and returns a raw `500` with the constraint/table name exposed in the UI. Reproduced end-to-end through the real UI at `/portal/<clientId>/account`. Filed as **BUG-90**.
2. **`PATCH /api/templates/[id]` — `is_public` has no type validation** (sibling field `is_pinned` does). `{"is_public":"banana"}` → `500` leaking `invalid input syntax for type boolean`; `{"is_public":"yes"}` / `{"is_public":1}` are silently coerced to `true` and accepted with `200`, bypassing intended validation. Filed as **BUG-91**.
3. **`POST /api/programmes/[id]/assign` — `startDate` accepts implausible years** (1900, 9999) because it uses native `new Date()` + `isNaN` instead of the codebase's own `isValidDateString` helper (which every other date-accepting route uses specifically to guard against this). Low severity — no crash, but could corrupt a client's schedule with nonsense dates if the programme had real session content. Filed as **BUG-92**.
4. **`POST /api/bug-reports` — `page_title` has zero validation** (no typeof check, no length cap, no sanitization), unlike every sibling field in this route and codebase. Accepts arrays/objects and multi-thousand-char strings. Not currently exploitable (all render paths escape it) but reaches an external Notion export unchecked. Filed as **BUG-93 report itself is also test data — see Cleanup candidates**. Filed as **BUG-95** (the finding); the two reports that demonstrated it (refs 93, 94) are inert test rows.
